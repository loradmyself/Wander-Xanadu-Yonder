# 功能规格（FEATURES）

> 状态：草案 v0.2 · 待评审（v0.2 增补视觉与摄像头能力）
> 范围：平台固件（L1/L2）与工具运行框架（L2.5）；动态应用（L3）只列候选，另行确定
> 优先级：**P0** = v1.0 必须（缺了产品不成立）· **P1** = 应有（v1.x 补齐）· **P2** = 以后/可选

## 一、分层定义

| 层 | 内容 | 谁负责 | 是否进固件 |
| --- | --- | --- | --- |
| L0 | 芯片、SiFli SDK、RT-Thread、驱动 | SDK / 板级 | 是 |
| L1 | 平台底座：系统、显示、输入、音频、视觉、连接、存储、电源、USB | 平台组 | 是 |
| L2 | 平台服务：AI Core、多模态、语音链路、门户、OTA、安全 | 平台组 | 是 |
| L2.5 | 工具运行框架：清单、注册表、调度、权限、安装 | 平台组 | 是 |
| L3 | 动态应用（`.xzp`）：每个应用 = 页面 + 工具集 | 应用组 / 第三方 | 否，运行时安装 |

**判断标准**：凡是"没有它任何应用都跑不起来"的进 L1；凡是"多个应用都要用、但不该各写一遍"的进 L2；凡是"决定应用能不能被 AI 调用"的进 L2.5。

## 一点五、感官清单（产品视角的自检表）

玩伴类产品的体验是否"完整"，取决于它有没有五官。缺一项，用户就会觉得"它有点呆"，而且说不清哪里不对。这张表用来反查功能清单有没有偏科：

| 感官 | 硬件 | 平台能力 | 对应功能组 |
| --- | --- | --- | --- |
| 听 | PDM/I2S 麦克风 | VAD、STT、打断 | D 音频 · J AI |
| 说 | 扬声器 + PA | TTS 流式播报、混音 | D 音频 · J AI |
| 看 | 摄像头 | 采集、图像理解（VLM） | **I 视觉 · J AI** |
| 表情 | 屏 | 表情动画、情绪状态机 | B 显示 · J AI |
| 触 | 触摸 / 按键 / 马达 | 手势、按键、震动反馈 | C 输入 |

**结论：五项里"看"是最容易被漏掉、也最贵的一项**——它不只是加个摄像头，而是同时牵扯 ISP/带宽、PSRAM 预算、上传流量、隐私合规与模型成本。

### I. 视觉与摄像头（CAM）

> 「AI 看见世界」的硬件入口。设计原则：**能做小的不上大的，能直出 JPEG 的不走 YUV**——MCU 上视觉的瓶颈几乎永远是带宽与 PSRAM，不是算法。

| ID | 功能 | 优先级 | 说明 / 依赖 |
| --- | --- | --- | --- |
| F-CAM-01 | 摄像头抽象层（统一 `capture` API，屏蔽 sensor 差异） | P0 | 上层代码不绑 sensor 型号，换料不改应用 |
| F-CAM-02 | Sensor 驱动：DVP 并口 或 MIPI-CSI | P0 | **需确认芯片与 SDK 支持哪种**，两者走线/时钟/功耗差别大 |
| F-CAM-03 | JPEG 直出采集（优先选自带压缩的 sensor） | P0 | 免 ISP、免 600KB 级帧缓冲，是最关键的选型决策 |
| F-CAM-04 | 分辨率与质量档位（预览 320×240 / 拍照 640×480–1280×720） | P0 | 按识别精度与上传流量两端平衡 |
| F-CAM-05 | 实时预览（5–15fps，屏上取景） | P1 | 不追高帧率，追"能看清对没对准" |
| F-CAM-06 | 图像处理：旋转 / 镜像 / 裁剪 / 缩放 / EXIF 方向 | P0 | 模组装配方向各异，必须软件可纠 |
| F-CAM-07 | 曝光 / 白平衡 / 增益（sensor 内置或简单算法） | P0 | 逆光与室内暖光是翻车高发场景 |
| F-CAM-08 | 对焦：定焦 或 VCM 自动对焦 | P1 | AF 增加 VCM 驱动、供电与成本，定焦先跑通 |
| F-CAM-09 | 补光：白光 LED + PWM，限流、限时、限温 | P1 | **眼睛安全**：亮度与距离必须限制，不做无上限输出 |
| F-CAM-10 | 电源与时钟管理：按需上电、拍完立即断电 | P0 | 摄像头待机电流大，不彻底断电会毁掉待机指标 |
| F-CAM-11 | 隐私指示：拍照灯 / 快门音 / 屏上提示 | P0 | 合规与信任的底线，硬件需预留 LED 控制脚 |
| F-CAM-12 | 帧缓冲与丢帧策略，PSRAM 占用上限 | P0 | 与 F-SYS-11 联动，宁可丢帧不可 OOM |
| F-CAM-13 | 连拍 / 短视频（MJPEG，5–10fps） | P2 | 存储与带宽压力大，首版不做 |
| F-CAM-14 | 摄像头模组形态（前置 / 可翻转 / 外接） | P2 | 由结构件与外观念决定 |

**选型建议（需按实际模组确认参数）**：优先选**自带 JPEG 输出、支持 640×480@15fps、I2C 配置、单 3.3V/2.8V 供电、带可关断使能**的模组，例如 GC0308 / OV2640 / OV5640 这一类（具体型号、封装、供货与是否支持 DVP/CSI 需查最新数据手册与供应商，不在此臆断）。定焦 + JPEG 直出 + 软件旋转，是 MCU 上最省心的组合。

## 五、v1.0 最小可用集（MVP）

只保留"没有它就不是玩伴产品"的部分，共 **31 项**（v0.2 因视觉加入而扩容，见下方代价说明）：

系统 F-SYS-01/02/05/07/09/10/11 · 显示 F-DISP-01/02/03/05/08 · 输入 F-INP-01/02/04 · 音频 F-AUD-01/02/03 · 无线 F-NET-01/02/03/04/09 · 存储 F-STO-01/02/03 · 电源 F-PWR-01/02/03/04/05 · **视觉 F-CAM-01/02/03/04/06/07/10/11/12** · AI F-AI-01/02/03/04/05/08/09/11/**17/19** · 工具 F-TOOL-01/02/03/04/05/07/08/09/**13** · 安全 F-SEC-01/02/03/**08/09/10**

其余全部延后到 v1.x。**判断依据：能完成"按住说话 → 语音回答 → 顺手帮你建个闹钟 → 拿起看一眼并说出看到什么"这一条链路，且不掉电、不死机、不越权、不偷拍。**

**扩容代价（必须一起评估，别只看功能表）**：

| 项 | 影响 |
| --- | --- |
| 进度 | 视觉链路（驱动 + 采集 + 压缩 + 上传 + 回显）约等于再加一个 P1 阶段，建议单独排 3–4 周 |
| 内存 | PSRAM 从 4MB 提到 8MB 更稳；单帧 JPEG 缓冲 + 解码缓冲要吃 200–400KB |
| 功耗 | 摄像头上电瞬间电流尖峰，必须做软启动（限流）与拍后立即断电，否则待机指标破功 |
| 成本 | 模组 + FPC + 补光 LED + 指示 LED + 可能的 VCM，BOM 增加可观 |
| 流量 | 每次图像调用 = 数十 KB 上行 + 多模态 token 费用，比纯文本贵一个量级 |

## 六、硬件前提（不满足则对应功能降级或删除）

| 功能 | 硬件前提 | 影响 |
| --- | --- | --- |
| USB Host（F-USB-07） | 5V VBUS 升压、限流开关、VBUS 检测脚、ESD 保护 | 缺一则只能做 Device |
| AEC / 降噪（F-AUD-06） | 双麦，或扬声器参考信号回采 | 单麦做不好，别承诺 |
| 电量计（F-PWR-02） | 库仑计或分压 ADC + 标定数据 | 无标定则电量跳变 |
| 表情动画（F-DISP-05） | LCD/AMOLED，非墨水屏 | 墨水屏只能做静态表情卡 |
| KWS 唤醒（F-INP-05） | 算力余量 + 模型存储 | 首版用按键 |
| 蓝牙音频（F-AUD-07） | 蓝牙协议栈支持 A2DP、PA 功放 | 无则走外放 |
| TF 卡（F-STO-02） | 卡座检测脚 + 电源开关 | 无则应用只能装内部 |
| 摄像头（F-CAM-01/02） | 芯片支持 DVP 或 MIPI-CSI；FPC 座、MCLK/PCLK 走线、独立 LDO 或可关断电源 | 无接口则"看见世界"整体不可做 |
| JPEG 直出（F-CAM-03） | sensor 自带 JPEG 编码 | 只有 YUV/RAW 时需软件编码，MCU 上基本不可行，需换模组 |
| 补光与指示（F-CAM-09/11） | 白光 LED + 限流电阻 + 独立控制脚；指示 LED 与主控分开供电 | 缺指示灯则隐私合规不达标 |
| 多模态模型（F-AI-17） | 云端支持图像输入的 VLM，且账号/额度可用 | 无则只能做本地检测，能力大打折扣 |

## 七、资源预算（需按实际配置核实）

| 项 | 估算 | 备注 |
| --- | --- | --- |
| 固件 + 平台 | 2–3 MB | 含 RT-Thread、LVGL、网络栈 |
| 中文字库 | 3–8 MB | 按字符集范围浮动，最大变量 |
| 表情 / 音效资源 | 2–5 MB | 序列帧比 Lottie 更占空间 |
| 应用安装区 | ≥ 8 MB | 按目标应用数量估 |
| Flash 合计建议 | ≥ 16 MB NOR | 低于此需外挂或裁剪字库 |
| PSRAM | ≥ 4 MB，建议 8 MB | LVGL 双缓冲 + 音频 + 流式文本缓冲 |
| 图像缓冲 | 200–400 KB | 单帧 JPEG + 解码/缩放缓冲，走 PSRAM |
| 运行内存 | 稳态 < 60%，峰值 < 85% | 超过则休眠唤醒易失败 |

> 以上为估算区间，**必须按最终 BOM 与屏分辨率实测确认**，不能直接当结论用。
