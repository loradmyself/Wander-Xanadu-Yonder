## 背光/PA11 结论纠错（重要，推翻 11-23 的部分判断）
- 11-23 曾判断"PA11 在本板是 WS2812、背光恒亮不需要 PWM"——**此判断错误**，以原理图为准纠正。
- 权威证据：`datasheet/SCH_SF32LB57-DevKit-LCD-V1.1_2026-11-18.pdf`
  - Change list（第 2 页）：「RGB-LED 的 IO 由 PA11 改为 PA08」。
  - LCDC-DPI-RGB888 页：`PA_11 → FPC 34 脚 → BL_PWM`，即 **PA11 就是屏幕背光 PWM**。
  - LED 页：`PA_08 → R6(0Ω) → WS2812B DI`，标注「Shared GPIO with TF_CLK」，即 **RGB 数据线在 PA08**。
- 结论：PA11 只做背光、PA08 只做 RGB LED，两者物理分开。用户记忆中的"USB-Display 工程踩过此坑"与 V1.1 改板记录吻合。
- 当前代码与此相反（bug 根因）：
  - `boards/Wander-Xanadu-Yonder_base/bsp_pinmux.c`：`HAL_PIN_Set(PAD_PA11, GPTIM1_CH4, ...)` 把 WS2812 放在 PA11。
  - `boards/Wander-Xanadu-Yonder_base/bsp_lcd_tp.c` 第 102 行：PA11 的 `GPTIM2_CH2` 背光复用被注释，仅 QADSPI 分支第 129 行用 PA45。
  - `Kconfig.board:24`：`LCD_BACKLIGHT_CONTROL_PIN default 11 if DPI`（值是对的，但 pinmux 没配）。
  - `rtconfig.h`：`LCD_USING_PWM_AS_BACKLIGHT=1`，pwmt2 CH2 注册 `lcdlight` 设备，但 DPI 下 GPTIM2_CH2 未复用到任何物理脚 → 背光 PWM 出不来。
- 修复方案（尚未改代码，等用户确认）：
  - RGB LED：`PAD_PA08` 复用为 PWM 通道。注意 SF32LB57 PA08 pinmux 表（`drivers/cmsis/sf32lb57x/bf0_pin_const.c`）只有 GPIO/LCDC1_SPI_DIO3/SD1_CLK/DBG_DO6，**没有 GPTIM1_CH4**——需确认 PA08 的 PWM 能力，若不支持则 RGB 改走其他通道或接受 WS2812 不亮。
  - 背光：DPI 分支恢复 `HAL_PIN_Set(PAD_PA11, GPTIM2_CH2, PIN_NOPULL, 1)`；核对 Kconfig 的 pin=11。
- 未编译验证：shell 无 SIFLI_SDK / SCons。

## UI 逻辑框架建议（第二轮，用户明确只要讨论不写代码）
- 用户判断获认可：逻辑框架（导航模型/转场语义/反馈契约/资源契约）必须先于工程框架完善；视觉风格可后套。
- 转场采用 Material Motion Six Patterns 映射到本工程：容器变换（卡片→详情/表情→全屏）、前进后退（设置→主题）、横向同级（底部 Tab/主题预览）、顶层切换（对话↔桌面快淡入淡出）、进出场（按住说话波形/TTS 条）、骨架屏（LLM 流式气泡）。
- 四条转场纪律：统一方向、先淡出再淡入（禁交叉淡化）、拒绝跳切、退场快于进场；小屏时长比 M3 手机值（200–500ms）再压缩，退场约 150ms / 进场约 250ms；进场 ease_out、退场 ease_in。
- 点击反馈三通道：视觉按下态 0ms 即时生效、松开 120ms 回弹；触觉短震 20–40ms（马达 P1，无则视觉加倍）；听觉轻音 30ms 可关且不打断 TTS。
- 图标资源契约：初版禁止用文字占位替代图片；用固定「图标槽位清单」+ 单色遮罩图 + LVGL image recolor 实现一套图标多主题复用；槽位缺失回退基准主题；表情动画（F-DISP-05）作为独立资源类别，按情绪状态机映射动画 ID。
- 参考资料：m3.material.io/styles/motion/transitions 与 /easing-and-duration/tokens-specs；docs.lvgl.io/9.4 的 styles/transitions.html、9.5 的 main-modules/animation.html。

- 架构约定：① 页面不写色值，全部令牌 + `wxy_reg()` 登记；② 场景启动时全建好，只切显隐/透明度，点击不 malloc；③ 界面只认"碟"，`wxy_ui_disc("timer")` 即可驱动，供 AI Core 复用。
- 唱臂是真物理模型：支点 (952,96)、臂长 470，针尖 = 支点 + 470×(cosθ,sinθ)，θ=132°(外圈)…152°(内圈)，音乐播放随进度再推进 18°；用 lv_trigo_sin/cos 整数三角，无浮点。
- 关键实现坑（已修）：
  1. `WXY_DISC_COUNT` 是 `const uint8_t`，不能做数组维度（file scope VLA 报错）→ 加 `WXY_DISC_MAX 10` 宏。
  2. 主题注册表要挂 `LV_EVENT_DELETE` 自动摘除，否则运行时重建的图标（播放/暂停、碟面图标、陪伴脸）被删后切主题会写已释放内存。
  3. 计时页 100ms 刷新会重建图标 → 只在播放态变化时重建，否则持续堆碎片。
  4. 唱臂/碟仓必须抬到读碟窗之上（原型 arm z=8 > content z=5）：唱机挂在屏幕根上，`wxy_tt_raise()` 在页面建好后 move_foreground；泛层另建 `s_overlay` 层盖在唱臂上。
  5. 换碟动画期间 `paint()` 不能直接改唱针角度，否则和抬针动画打架 → 加 s_swapping 标志，由 swap_ready 收尾。
- 明确偏差（已写进 docs/UI-FRAMEWORK.md）：无 blur（用透明度+位移代替）、唱片不整体旋转（560px 每帧重绘太大，改成读纹光点绕行）、碟名英文（内置 CJK 字体只覆盖 53% 常用字，实测缺"对谈桌设题碟仓"等）、涟漪用三根微光条、碟心轴孔未画。
- 构建：main.bin 681,560 B（此前壳子 660,896 B，框架净增约 20KB）；LVGL 走 RT-Thread 堆（`LV_USE_RTTHREAD_MALLOC=y`，不是 64KB 内建池），`ui ready` 日志会打印 heap used/total/peak 供上板观察。
- 文档：`docs/UI-FRAMEWORK.md`（分层、碟状态机、唱臂几何、加一屏三步、偏差账、上板验收清单）。

- 编译环境两个真坑（已写进 docs/BUILD.md 常见报错）：
  1. Git Bash 里 `export PATH="C:/.../bin:$PATH"` 会被 MSYS 转成 `C;F:/...` 垃圾串，裸名 `arm-none-eabi-gcc`（SDK 里 `rtconfig.CC` 就是裸名，靠 PATH 找）解析不到 → 报 `Generating ... link_copy.lds ... 系统找不到指定的文件`，看着像链接脚本的问题其实是编译器没找到。必须用 `/c/...` 形式。
  2. `PYTHONPATH` 必须分号分隔（Windows Python 不认冒号），否则 `ModuleNotFoundError: No module named 'building'`。
- 每次构建 stderr 都会有一条 `reg.exe` 被安全策略拦截（SDK 探测 Keil/IAR 注册表），与 gcc 编译链接无关，忽略。
